\begin{abstract}
This report presents a student-led comparative study of medical question answering with large language models on the Medical Flashcards dataset. We compare closed-book generation, prompt engineering, and retrieval-augmented generation (RAG), and we include a symbolic fine-tuning step to validate the full pipeline under compute constraints. The project was organized after a brainstorming phase focused on three priorities: reproducibility, realistic compute budget, and medical safety. Evaluation combines lexical metrics (ROUGE, BLEU), local LLM-as-a-judge scoring, latency/cost indicators, and qualitative reading of outputs. We discuss both gains and failure modes, with explicit attention to hallucination risks in medical contexts.

\section{Introduction}

Medical question answering is a challenging task that requires both factual accuracy and appropriate response formatting. The proliferation of large language models (LLMs) has opened new possibilities for automating medical knowledge retrieval, but also raised concerns about reliability and hallucinations.

This project explores various approaches to answering medical questions from a flashcard-style dataset, comparing:

\begin{itemize}
    \item \textbf{Closed-book generation}: LLMs answering from parametric knowledge
    \item \textbf{Prompt engineering}: Optimizing instructions for better outputs
    \item \textbf{Fine-tuning}: Domain adaptation with LoRA/QLoRA
    \item \textbf{Retrieval-Augmented Generation (RAG)}: Grounding responses in retrieved knowledge
\end{itemize}

Our objectives are:
\begin{enumerate}
    \item Compare performance across model sizes and providers
    \item Evaluate the impact of different prompting strategies
    \item Assess the benefits of fine-tuning on domain-specific data
    \item Analyze RAG for knowledge grounding and hallucination reduction
    \item Provide honest discussion of limitations and practical considerations
\end{enumerate}

\subsection{Project Framing and Brainstorming}

At the beginning of the project, we listed many possible directions (cloud APIs, local models, multiple retrievers, full fine-tuning, prompt variants). To keep the work both rigorous and feasible, we structured the exploration around controlled comparisons:
\begin{itemize}
    \item \textbf{Prompt axis}: same model, different prompts (strict, flashcard, uncertainty).
    \item \textbf{Retrieval axis}: same generator, different external sources (Wikipedia vs web) and different top\_k.
    \item \textbf{Evaluation axis}: combine automatic metrics, semantic judging, and manual qualitative checks.
\end{itemize}
This framing helped us avoid random trial-and-error and keep a coherent experimental narrative.

\section{Methods}

\subsection{Closed-Book Generation}

Direct question answering using pre-trained language models without additional context. The model must rely entirely on knowledge encoded during pre-training.

\textbf{Models evaluated}:
\begin{itemize}
    \item OpenAI GPT-4o-mini (cloud API, cost-efficient)
    \item Llama 3.1 8B via Ollama (local inference)
    \item Mistral 7B via OpenRouter (free tier)
    \item Flan-T5-base (CPU fallback)
\end{itemize}

\subsection{Prompt Engineering}

We evaluate three prompting strategies:

\begin{enumerate}
    \item \textbf{One-sentence strict}: Explicitly requests single-sentence answers
    \begin{quote}
    \textit{``Answer the following medical question in exactly one clear, concise sentence.''}
    \end{quote}
    
    \item \textbf{Flashcard style}: Frames the task as flashcard completion
    \begin{quote}
    \textit{``Complete this medical flashcard with a brief, accurate answer.''}
    \end{quote}
    
    \item \textbf{Uncertainty allowed}: Permits ``Insufficient information'' responses
    \begin{quote}
    \textit{``If you are uncertain, respond with `Insufficient information.'\,''}
    \end{quote}
\end{enumerate}

\subsection{Fine-tuning with LoRA/QLoRA}

Parameter-efficient fine-tuning using Low-Rank Adaptation:

\begin{itemize}
    \item \textbf{Method}: QLoRA with 4-bit quantization
    \item \textbf{LoRA rank}: 16
    \item \textbf{LoRA alpha}: 32
    \item \textbf{Target model}: TinyLlama-1.1B-Chat
    \item \textbf{Training sizes}: 1k, 5k, 20k examples
\end{itemize}

This approach allows fine-tuning with limited GPU memory ($\sim$8GB VRAM).

\subsection{Retrieval-Augmented Generation (RAG)}

Combining retrieval with generation for knowledge grounding:

\begin{enumerate}
    \item \textbf{Retrieve}: Query Wikipedia for relevant medical content
    \item \textbf{Format}: Inject retrieved context into prompt
    \item \textbf{Generate}: LLM produces answer conditioned on context
\end{enumerate}

\textbf{Ablations}:
\begin{itemize}
    \item Number of retrieved documents (top\_k = 3 vs 5)
    \item Maximum context length
    \item Retriever type (Wikipedia vs Web)
\end{itemize}

\section{Evaluation Methodology}

\subsection{Automatic Metrics}

\subsubsection{ROUGE-L}

Longest common subsequence F1 score between prediction and reference. Captures word-level overlap while respecting word order.

\textbf{Limitation}: Penalizes valid paraphrases and synonyms.

\subsubsection{BLEU}

N-gram precision with brevity penalty, computed using sacrebleu. Standard machine translation metric.

\textbf{Limitation}: Very strict for short-form QA; synonyms receive zero credit.

\subsection{LLM-as-a-Judge}

For this final report, we use a local judge model (\texttt{google/flan-t5-large}) to assess semantic equivalence. We initially planned to use a cloud judge, but we prioritized a fully reproducible local pipeline:

\begin{itemize}
    \item \textbf{Score 2} (Correct): Semantically equivalent to reference
    \item \textbf{Score 1} (Partial): Some correct information, but incomplete
    \item \textbf{Score 0} (Wrong): Incorrect, irrelevant, or contradictory
\end{itemize}

\textbf{Consistency verification}: We re-judge a subset of examples to estimate judge reliability.

\subsection{Format Statistics}

Additional metrics for output quality:
\begin{itemize}
    \item Average answer length (characters, words)
    \item Multi-sentence percentage
    \item Empty response rate
    \item ``Insufficient information'' rate (for uncertainty prompts)
\end{itemize}

\section{Qualitative Analysis}

Selected examples from each category (best, worst, controversial) are summarized below.

\subsection{Successful Cases}

\begin{itemize}
    \item The web-based RAG setup (\texttt{exp\_17\_rag\_hf\_web}) achieved the highest lexical scores (ROUGE-L 0.1582, BLEU 0.0003), outperforming the Wikipedia RAG variant and all closed-book local baselines.
    \item Among closed-book variants, the flashcard-style prompt (\texttt{exp\_13\_hf\_flan\_flashcard}) gave the strongest lexical alignment (ROUGE-L 0.1328), with concise outputs and low multi-sentence rate (3.75\%).
    \item Questions with explicit procedural wording (e.g., effects of ion transport, definition-style prompts) were generally handled better than broad clinical management questions.
    \item The strict one-sentence setup (\texttt{exp\_12\_hf\_flan\_strict}) improved consistency over the simple direct baseline (\texttt{exp\_11}), suggesting prompt structure matters even for the same model.
\end{itemize}

\subsection{Failure Cases}

\begin{itemize}
    \item The uncertainty-allowed prompt (\texttt{exp\_14}) collapsed into systematic abstention: 100\% ``Insufficient information'', near-zero ROUGE-L (0.0004).
    \item Some answers were fluent but medically off-target (e.g., wrong entities for enzyme/pathogen questions), indicating factual brittleness of small local models.
    \item Increasing RAG context from top\_k=3 to top\_k=5 degraded quality (ROUGE-L 0.0866 \(\rightarrow\) 0.0576) while increasing latency (925ms \(\rightarrow\) 1451ms), suggesting context-noise effects.
    \item Long multi-concept questions (diagnosis + treatment + mechanism) showed lower overlap and more generic responses.
\end{itemize}

\subsection{Controversial Cases}

Several experiments show metric-judge divergence:

\begin{itemize}
    \item The uncertainty prompt has the lowest lexical overlap but a near-partial judge mean (0.9875), showing that abstention can be interpreted as ``partially acceptable'' by the local judge while remaining uninformative for QA.
    \item RAG web has the best lexical scores, but judge-correct remains low (4\%), indicating many outputs are still treated as incomplete rather than fully correct.
    \item Judge means cluster near 1.0 across methods (large partial class), so judge outputs should be treated as supportive signals, not final ground truth.
\end{itemize}

\section{Discussion}

\subsection{Key Findings}

\begin{enumerate}
    \item \textbf{Retrieval source matters.} Web RAG (\texttt{exp\_17}) outperformed Wikipedia RAG and closed-book variants on ROUGE/BLEU in this setup, suggesting broader retrieval coverage helped lexical alignment.
    \item \textbf{Prompt engineering remains important.} Flashcard prompting substantially improved closed-book quality versus simple direct prompting.
    \item \textbf{More retrieved context is not always better.} The top\_k=5 RAG ablation increased latency and reduced quality versus top\_k=3.
    \item \textbf{Abstention prompting requires calibration.} The uncertainty prompt over-triggered abstention (100\%), making outputs safe but low-utility.
    \item \textbf{Compute-aware experimentation is feasible.} A fully local CPU pipeline still allowed us to compare several meaningful strategies and build a reproducible report.
\end{enumerate}

\subsection{Limitations}

\subsubsection{Dataset Limitations}

\begin{itemize}
    \item Flashcard format may not represent real clinical queries
    \item Single reference answer limits metric reliability
    \item Potential biases in medical knowledge coverage
    \item Focus on declarative knowledge, not clinical reasoning
\end{itemize}

\subsubsection{Evaluation Limitations}

\begin{itemize}
    \item ROUGE/BLEU penalize valid paraphrases
    \item Local LLM judge (\texttt{flan-t5-large}) showed strong bias toward score 1 (partial), limiting discriminative power
    \item Semantic equivalence is subjective in medical domain
    \item No gold-standard human evaluation
\end{itemize}

\subsubsection{Hallucination Risks}

\begin{itemize}
    \item All models can generate plausible but incorrect information
    \item RAG can retrieve irrelevant or outdated content
    \item Fine-tuning may reinforce dataset biases
    \item Medical hallucinations can be dangerous
\end{itemize}

\subsection{Practical Recommendations}

Based on our findings:

\begin{itemize}
    \item \textbf{For low-budget student settings}: Start with local closed-book + prompt engineering, then add one RAG variant for comparison.
    \item \textbf{For robust analysis}: Always report lexical metrics, semantic judging, and qualitative examples together.
    \item \textbf{For RAG tuning}: Test top\_k carefully; larger context can increase noise and latency.
    \item \textbf{Critical}: Never deploy medical QA without human oversight.
\end{itemize}

\section{Conclusion}

This project provides a comparative and reproducible study of medical QA strategies under realistic compute constraints. The main lesson is not that one method ``wins'' in every metric, but that design choices (prompt style, retrieval source, top\_k, abstention policy) have measurable and interpretable effects on output quality and latency.

\textbf{Main contributions}:
\begin{enumerate}
    \item Reproducible end-to-end pipeline for medical QA experiments.
    \item Structured comparison across closed-book, prompt engineering, and multiple RAG setups.
    \item Multi-view evaluation (ROUGE/BLEU, local judge, latency, qualitative analysis).
    \item Transparent discussion of limits, including judge bias and compute constraints.
\end{enumerate}

\textbf{Future work}:
\begin{itemize}
    \item Human evaluation for ground truth
    \item Specialized medical retrievers
    \item Confidence calibration for uncertainty
    \item Multi-turn dialogue for clarification
\end{itemize}

\section*{Ethical Statement}

This project is for educational purposes only. The generated answers should never be used as medical advice. Healthcare decisions should always involve qualified professionals. We acknowledge the risks of AI hallucinations in medical contexts and emphasize the importance of human oversight.
