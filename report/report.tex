\begin{abstract}
This report presents a comparative medical question-answering study conducted in a student project setting on the Medical Flashcards dataset. We evaluate three families of approaches: local closed-book generation, retrieval-augmented generation (RAG), and QLoRA fine-tuning on Google Colab (1k/5k/20k training examples). Beyond reporting scores, we document implementation choices and practical constraints (compute budget, reproducibility, and safety). The final protocol combines lexical overlap (ROUGE-L, BLEU), a local semantic judge (\texttt{flan-t5-large}), latency/format statistics, and qualitative error analysis. The strongest lexical results in our run are obtained after fine-tuning (\texttt{finetune\_5k}: ROUGE-L 0.2757, BLEU 0.1428), while the best non-fine-tuned configuration is web-based RAG (\texttt{exp\_17}: ROUGE-L 0.1582). We also highlight failure modes (over-abstention under uncertainty prompting, judge bias toward partial scores) and discuss what is still required for clinical-grade reliability.

\section{Introduction}

Medical question answering is a challenging task that requires both factual accuracy and appropriate response formatting. The proliferation of large language models (LLMs) has opened new possibilities for automating medical knowledge retrieval, but also raised concerns about reliability and hallucinations.

This project explores various approaches to answering medical questions from a flashcard-style dataset, comparing:

\begin{itemize}
    \item \textbf{Closed-book generation}: LLMs answering from parametric knowledge
    \item \textbf{Prompt engineering}: Optimizing instructions for better outputs
    \item \textbf{Fine-tuning}: Domain adaptation with LoRA/QLoRA
    \item \textbf{Retrieval-Augmented Generation (RAG)}: Grounding responses in retrieved knowledge
\end{itemize}

Our objectives are:
\begin{enumerate}
    \item Compare performance across model sizes and providers
    \item Evaluate the impact of different prompting strategies
    \item Assess the benefits of fine-tuning on domain-specific data
    \item Analyze RAG for knowledge grounding and hallucination reduction
    \item Provide honest discussion of limitations and practical considerations
\end{enumerate}

\subsection{Project Framing and Brainstorming}

At the beginning of the project, we listed many possible directions (cloud APIs, local models, multiple retrievers, full fine-tuning, prompt variants). To keep the work both rigorous and feasible, we structured the exploration around controlled comparisons:
\begin{itemize}
    \item \textbf{Prompt axis}: same model, different prompts (strict, flashcard, uncertainty).
    \item \textbf{Retrieval axis}: same generator, different external sources (Wikipedia vs web) and different top\_k.
    \item \textbf{Evaluation axis}: combine automatic metrics, semantic judging, and manual qualitative checks.
\end{itemize}
This framing helped us avoid random trial-and-error and keep a coherent experimental narrative.

\subsection{Research Questions and Success Criteria}

To keep the project academically focused, we translated our brainstorming into concrete research questions:
\begin{itemize}
    \item \textbf{RQ1 (Prompting):} With the same local model, how much can prompt design improve medical QA quality and output format?
    \item \textbf{RQ2 (Grounding):} Does RAG improve answer quality compared with closed-book generation, and under which retrieval settings?
    \item \textbf{RQ3 (Adaptation):} Does LoRA/QLoRA fine-tuning on domain data provide measurable gains over local non-fine-tuned baselines?
\end{itemize}

Success was defined as improvement that is not only visible on one metric, but coherent across at least three dimensions: lexical score, judge score, and qualitative plausibility.

\section{Methods}

\subsection{Closed-Book Generation}

Direct question answering using pre-trained language models without additional context. The model must rely entirely on knowledge encoded during pre-training.

\textbf{Models evaluated}:
\begin{itemize}
    \item OpenAI GPT-4o-mini (cloud API, cost-efficient)
    \item Llama 3.1 8B via Ollama (local inference)
    \item Mistral 7B via OpenRouter (free tier)
    \item Flan-T5-base (CPU fallback)
\end{itemize}

\subsection{Prompt Engineering}

We evaluate three prompting strategies:

\begin{enumerate}
    \item \textbf{One-sentence strict}: Explicitly requests single-sentence answers
    \begin{quote}
    \textit{``Answer the following medical question in exactly one clear, concise sentence.''}
    \end{quote}
    
    \item \textbf{Flashcard style}: Frames the task as flashcard completion
    \begin{quote}
    \textit{``Complete this medical flashcard with a brief, accurate answer.''}
    \end{quote}
    
    \item \textbf{Uncertainty allowed}: Permits ``Insufficient information'' responses
    \begin{quote}
    \textit{``If you are uncertain, respond with `Insufficient information.'\,''}
    \end{quote}
\end{enumerate}

\subsection{Fine-tuning with LoRA/QLoRA}

Parameter-efficient fine-tuning using Low-Rank Adaptation:

\begin{itemize}
    \item \textbf{Method}: QLoRA with 4-bit quantization
    \item \textbf{LoRA rank}: 16
    \item \textbf{LoRA alpha}: 32
    \item \textbf{Target model}: TinyLlama-1.1B-Chat
    \item \textbf{Training sizes}: 1k, 5k, 20k examples
\end{itemize}

This approach allows fine-tuning with limited GPU memory ($\sim$8GB VRAM).

\subsection{Retrieval-Augmented Generation (RAG)}

Combining retrieval with generation for knowledge grounding:

\begin{enumerate}
    \item \textbf{Retrieve}: Query Wikipedia for relevant medical content
    \item \textbf{Format}: Inject retrieved context into prompt
    \item \textbf{Generate}: LLM produces answer conditioned on context
\end{enumerate}

\textbf{Ablations}:
\begin{itemize}
    \item Number of retrieved documents (top\_k = 3 vs 5)
    \item Maximum context length
    \item Retriever type (Wikipedia vs Web)
\end{itemize}

\subsection{Fair Comparison Protocol}

To keep comparisons meaningful, we used a simple protocol:
\begin{itemize}
    \item same evaluation split per comparison block (mainly \texttt{tiny\_test}),
    \item deterministic decoding (temperature 0.0),
    \item one answer per question (no reranking),
    \item identical evaluation pipeline for every predictions file (\texttt{metrics + judge + qualitative}).
\end{itemize}
This protocol does not eliminate all bias, but it prevents the most common unfair comparison issues (different sampling settings or different post-processing between methods).

\section{Evaluation Methodology}

\subsection{Automatic Metrics}

\subsubsection{ROUGE-L}

Longest common subsequence F1 score between prediction and reference. Captures word-level overlap while respecting word order.

\textbf{Limitation}: Penalizes valid paraphrases and synonyms.

\subsubsection{BLEU}

N-gram precision with brevity penalty, computed using sacrebleu. Standard machine translation metric.

\textbf{Limitation}: Very strict for short-form QA; synonyms receive zero credit.

\subsection{LLM-as-a-Judge}

For this final report, we use a local judge model (\texttt{google/flan-t5-large}) to assess semantic equivalence. We initially planned to use a cloud judge, but we prioritized a fully reproducible local pipeline:

\begin{itemize}
    \item \textbf{Score 2} (Correct): Semantically equivalent to reference
    \item \textbf{Score 1} (Partial): Some correct information, but incomplete
    \item \textbf{Score 0} (Wrong): Incorrect, irrelevant, or contradictory
\end{itemize}

\textbf{Consistency verification}: We re-judge a subset of examples to estimate judge reliability.

\subsection{Format Statistics}

Additional metrics for output quality:
\begin{itemize}
    \item Average answer length (characters, words)
    \item Multi-sentence percentage
    \item Empty response rate
    \item ``Insufficient information'' rate (for uncertainty prompts)
\end{itemize}

\subsection{Main Quantitative Observations}

\begin{enumerate}
    \item \textbf{Fine-tuning clearly dominates lexical metrics in our run.} The best score is obtained by \texttt{finetune\_5k} (ROUGE-L 0.2757, BLEU 0.1428), followed by \texttt{finetune\_20k} (ROUGE-L 0.2714, BLEU 0.1445) and \texttt{finetune\_1k} (ROUGE-L 0.2607, BLEU 0.1299).
    \item \textbf{Data scaling helps, but not strictly monotonically for all metrics.} Moving from 1k to 5k improves both ROUGE-L and BLEU; moving to 20k gives the highest judge mean (1.24) but a slightly lower ROUGE-L than 5k, suggesting a mild quality/stability trade-off rather than a simple ``more data always better'' effect.
    \item \textbf{Prompt engineering remains meaningful even without fine-tuning.} Within local closed-book runs, flashcard prompting (\texttt{exp\_13}, ROUGE-L 0.1328) outperforms strict one-sentence prompting (\texttt{exp\_12}, 0.1025) and simple direct prompting (\texttt{exp\_11}, 0.0855).
    \item \textbf{RAG quality depends strongly on retrieval configuration.} Web retrieval (\texttt{exp\_17}, ROUGE-L 0.1582) is stronger than Wikipedia top-k=3 (\texttt{exp\_15}, 0.0866), while increasing to top-k=5 (\texttt{exp\_16}, 0.0576) hurts both quality and latency.

\end{enumerate}

\section{Qualitative Analysis}

Qualitative reading was performed from the generated HTML reports and manual inspection of representative examples across all families (closed-book, RAG, fine-tuned). The objective was not to cherry-pick only best outputs, but to understand recurring behavior patterns.

\subsection{Successful Cases}

\begin{itemize}
    \item Fine-tuned models (\texttt{finetune\_1k/5k/20k}) produce substantially richer medical content than non-fine-tuned local baselines, which is consistent with their higher ROUGE-L/BLEU values.
    \item \texttt{finetune\_20k} reaches the highest judge mean (1.24) and best correct rate among reported runs (24\%), suggesting improved semantic adequacy even when lexical gain over \texttt{finetune\_5k} is small.
    \item Among non-fine-tuned methods, web RAG (\texttt{exp\_17}) is the strongest lexical configuration (ROUGE-L 0.1582), showing that retrieval source quality matters.
    \item Flashcard prompting (\texttt{exp\_13}) improves both lexical overlap and output structure versus simple direct prompting, confirming that prompt format remains a high-leverage low-cost intervention.
\end{itemize}

\subsection{Failure Cases}

\begin{itemize}
    \item The uncertainty-allowed prompt (\texttt{exp\_14}) collapsed into systematic abstention: 100\% ``Insufficient information'', near-zero ROUGE-L (0.0004).
    \item Increasing RAG context from top\_k=3 to top\_k=5 degraded quality (ROUGE-L 0.0866 \(\rightarrow\) 0.0576) while increasing latency (925ms \(\rightarrow\) 1451ms), indicating retrieval noise and context dilution.
    \item Fine-tuned outputs are much longer (around 310 characters on average) and frequently multi-sentence, which can violate strict flashcard-style formatting constraints even when semantic content improves.
    \item Some biologically plausible but incorrect details remain in all families, especially on multi-step or multi-entity questions; this confirms that factual hallucination is reduced but not removed by fine-tuning.
\end{itemize}

\subsection{Controversial Cases}

Several experiments show metric-judge divergence:

\begin{itemize}
    \item \texttt{finetune\_5k} has the highest ROUGE-L (0.2757) but lower judge mean than \texttt{finetune\_20k}; lexical overlap and semantic adequacy do not rank models identically.
    \item The uncertainty prompt has the worst lexical metrics but a near-partial judge mean (0.9875), revealing that the local judge may reward safe abstention more than expected.
    \item Judge means remain concentrated around score 1 for many runs; therefore, the judge is useful as a complementary signal, not as a standalone verdict.
\end{itemize}

\section{Discussion}

\subsection{Key Findings}

\begin{enumerate}
    \item \textbf{Fine-tuning is the main performance lever in our setup.} The three fine-tuned runs dominate lexical metrics over all non-fine-tuned local baselines.
    \item \textbf{Prompt engineering is still valuable before expensive training.} Flashcard-style prompting gives clear gains over simple and strict prompts with almost no extra cost.
    \item \textbf{RAG behavior is configuration-sensitive.} Retrieval source and top-k materially change both quality and latency; ``more context'' is not automatically better.
    \item \textbf{Metric triangulation is mandatory.} ROUGE/BLEU, judge scores, latency, and qualitative reading can disagree; relying on a single metric would lead to overconfident conclusions.
    \item \textbf{The project reached a reproducible research baseline, not a deployable medical system.} We now have a coherent benchmark and ablation framework that can be extended, but safety validation remains insufficient for real clinical use.
\end{enumerate}

\subsection{Limitations}

\subsubsection{Dataset Limitations}

\begin{itemize}
    \item The flashcard format emphasizes concise factual recall, not full clinical reasoning workflows.
    \item Each question has a single reference answer, which can undervalue valid alternative phrasings.
    \item Our report-facing runs use small evaluation subsets for practical compute reasons; this improves iteration speed but increases variance.
    \item Topic coverage reflects the source dataset and may under-represent rare diseases or nuanced guideline-based decisions.
\end{itemize}

\subsubsection{Evaluation Limitations}

\begin{itemize}
    \item ROUGE/BLEU remain lexical metrics and penalize semantically correct paraphrases.
    \item The local judge (\texttt{flan-t5-large}) is useful but not neutral; score-1 concentration indicates limited discriminative granularity.
    \item Semantic adequacy in medicine is inherently context-dependent and can require specialist interpretation.
    \item We did not perform blinded expert annotation, so judge-based conclusions should be considered provisional.
\end{itemize}

\subsubsection{Hallucination Risks}

\begin{itemize}
    \item All model families in this study can generate fluent but incorrect medical statements.
    \item RAG can propagate retrieval errors (irrelevant snippets, outdated medical content).
    \item Fine-tuning improves style/overlap but can also amplify biases in the training corpus.
    \item In a medical context, even low-frequency hallucinations are high-risk; human validation is mandatory.
\end{itemize}

\subsection{Practical Recommendations}

Based on our findings, a pragmatic roadmap for similar projects is:

\begin{itemize}
    \item \textbf{Phase 1 (baseline)}: run a local closed-book baseline with two prompt variants before adding complexity.
    \item \textbf{Phase 2 (grounding)}: add one RAG setup and tune top-k conservatively (start with 3, not 5+ by default).
    \item \textbf{Phase 3 (adaptation)}: invest in QLoRA fine-tuning only after baseline instrumentation is stable.
    \item \textbf{Phase 4 (validation)}: combine lexical metrics, semantic judging, and manual review; do not present one metric as definitive.
    \item \textbf{Safety rule}: keep a strict ``education-only'' framing and explicit human oversight requirements.
\end{itemize}

\section{Conclusion}

This project delivers an end-to-end and reproducible comparison of medical QA strategies under realistic student constraints. The final version goes beyond a static benchmark: we iteratively improved the pipeline, executed Colab fine-tuning, and re-integrated quantitative and qualitative evidence into a coherent analysis.

The central takeaway is practical: system quality is highly sensitive to design choices that are often treated as ``implementation details'' (prompt format, retrieval source, top-k, judge setup, and training data size). In our experiments, fine-tuning provides the strongest gains, but it does not eliminate failure modes; prompt/RAG decisions still matter and safety risks remain.

\textbf{Main contributions}:
\begin{enumerate}
    \item Reproducible pipeline spanning generation, RAG, fine-tuning, evaluation, and report artifact generation.
    \item Controlled ablations on prompt style, retrieval configuration, and fine-tuning data size (1k/5k/20k).
    \item Multi-angle evaluation: lexical overlap, local semantic judging, latency/format statistics, and qualitative review.
    \item Transparent report of engineering issues and their impact on methodological validity.
\end{enumerate}

\textbf{Future work}:
\begin{itemize}
    \item Human expert evaluation with adjudication protocol (at least two annotators).
    \item Medical-source-constrained retrieval (guidelines/textbooks) with citation tracking.
    \item Better abstention calibration (confidence-aware uncertainty instead of fixed template wording).
    \item Comparative external judging (API judge + local judge) to quantify evaluator bias.
\end{itemize}
