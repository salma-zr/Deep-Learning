# Medical Question Answering Project (Reproducible)

This repository provides a complete, reproducible pipeline for a Medical QA study project. It covers closed-book baselines, prompt engineering, LoRA fine-tuning, and RAG, with standardized outputs and an auto-generated PDF report. The dataset is for study only and **must not** be used for medical advice.

## Quick start (TL;DR)
1. Install dependencies: `python -m pip install -U pip && python -m pip install -e .`
2. Set keys: `export OPENAI_API_KEY=...` and optionally `export OPENROUTER_API_KEY=...`
3. Run everything: `bash scripts/run_all.sh`
4. Build report only: `python -m src.report.build_report --config configs/report.yaml`

## Repository layout
- `data/`: dataset and splits (generated by scripts)
- `configs/`: YAML configs (one per experiment)
- `src/`: data, generation, rag, finetune, eval, report, utils
- `results/`: predictions, metrics, figures, report assets
- `scripts/`: run_all helpers
- `report/`: LaTeX report template

## Setup
Requirements:
- Python 3.11
- Optional: GPU for fine-tuning
- Optional: Ollama for local models

Install (editable mode):
`python -m pip install -e .`

Environment variables:
- `OPENAI_API_KEY` for OpenAI calls
- `OPENROUTER_API_KEY` for OpenRouter calls

## Step-by-step pipeline
1) Download dataset:
`python -m src.data.download_dataset --output data/raw/flashcards.jsonl`

2) Build splits (80/10/10 + tiny_test=200):
`python -m src.data.build_splits --input data/raw/flashcards.jsonl --seed 42`

3) RAG retrieval cache (Wikipedia):
`python -m src.rag.build_index --config configs/exp_rag_wiki_k3.yaml`

4) Fine-tuning prep + training:
`python -m src.finetune.prepare_finetune_data --config configs/exp_ft_1k.yaml`
`python -m src.finetune.finetune_lora --config configs/exp_ft_1k.yaml`

By default, fine-tuning configs use `symbolic: true` to avoid GPU requirements. Set it to `false` on a GPU machine.

5) Run generation for any experiment:
`python -m src.generation.closed_book --config configs/exp_cb_openai_mini.yaml`
`python -m src.rag.rag_generate --config configs/exp_rag_wiki_k3.yaml`

6) Judge (two passes for stability on a small subset):
`python -m src.eval.judge --config configs/judge.yaml --preds results/preds/cb_openai_mini.jsonl --output results/judge/cb_openai_mini.jsonl --exp-name cb_openai_mini`
`python -m src.eval.judge --config configs/judge.yaml --preds results/preds/cb_openai_mini.jsonl --output results/judge/cb_openai_mini_pass2.jsonl --exp-name cb_openai_mini --limit 50`

7) Metrics and qualitative HTML:
`python -m src.eval.compute_metrics --config configs/exp_cb_openai_mini.yaml`
`python -m src.eval.qualitative --config configs/exp_cb_openai_mini.yaml`

8) Build report:
`python -m src.report.build_report --config configs/report.yaml`

## Output format (standard)
Predictions: `results/preds/{exp_name}.jsonl`
- Fields: `id, question, reference, prediction, meta{model, prompt_id, latency_ms, token_usage, cost_estimate, retrieval_info}`

Scores: `results/scores/{exp_name}.csv`
- Aggregated metrics + latency + cost + format stats

Qualitative: `results/qualitative/{exp_name}.html`
- Best, worst, controversial examples

Report assets:
- `results/report_assets/*.tex` and `results/figures/*.png`

## Budget and cost control
- Default test limit is 500 examples.
- You can reduce cost by changing `data.limit` in configs.
- Pricing is configured per model in YAML (update to current prices).

## Troubleshooting
- Ollama errors: ensure `ollama serve` is running and the model is pulled.
- OpenAI errors: check `OPENAI_API_KEY`.
- OpenRouter errors: check `OPENROUTER_API_KEY` and model name.
- LaTeX build errors: install a TeX distribution or skip PDF build.

## Integrity and ethics
- No results are fabricated. Tables and figures are generated from files under `results/`.
- The dataset and outputs are for study only and **not** medical advice.
- All seeds, splits, and model parameters are logged.
